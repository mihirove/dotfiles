# Report template

Short by design. The reader has already read the ticket, so write only what is new. Skip any section with nothing new; never pad it with "none" or "no impact" rows.

```markdown
# [SKZ-XXX] <タイトル> 深掘り

## TL;DR
- 判定: <そのまま進める / スコープ変更 / 分割 / 要確認 / キャンセル候補> — <理由1行>
- 解決策の評価: <本質的か> / <短期・長期どちらとして適切か>
- 一番大事な確認事項: <1行>

## 1. 本当の課題（チケットに書かれていないものだけ）
- P1: <課題> — <出典: コメント(日付) / Slack / 関連チケット>
- 推測: <推測した動機> → 確認事項 #N

## 2. 解決策の評価
- 本質的か: <原因を取り除くか、症状への対処か。サービスの実態に合っているか>
- 短期 / 長期: <本質的な対策は何か・予定はあるか（チケット）>。<短期対応の保守コスト>
- 短期で進める場合: <1か所に閉じる方法、残す理由、外す条件>

## 3. 見落とし候補
1. <業務フロー / チーム>: <何が起きるか> — ✅確認済 / 🔍要確認
（該当するものだけ。影響のあるチームと、必要な周知もここに書く）

## 4. 代替案
| 案 | 内容 | 解決する課題 | 本質的? 短期/長期 | 工数 | リスク |
| -- | -- | -- | -- | -- | -- |
**推奨:** <案と理由1〜2行>

## 5. 確認事項
1. <質問> → <回答による分岐>

未確認: <開けなかったリンク・コード・データ>

### Linear コメント下書き
<宛先と、その人を選んだ理由を1行>
@... さん
...
```
